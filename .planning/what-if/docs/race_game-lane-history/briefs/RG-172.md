## Design (simplest thing that meets the rows; you may improve it, say why in the outbox)
1. New library `src/WhatIf.Planet.Runtime` (references `WhatIf.Planet`, `WhatIf.Planet.WorldGen`, `WhatIf.Planet.FarLayer`): `PlanetStreamer.Update(Vec3 cameraDir, double altitudeM, double dt)` on the main thread computes the wanted near set (level-15 sectors within `LoadRadius` 600 m, unload at 760 m, none above a ground clearance of 1500 m), the wanted regions (the camera's region + every region whose border is within `prefetchM`), enqueues jobs, integrates at most a bounded number of finished results per frame, and feeds `FarLayer` a `NearSet` of **ready** sectors only (the hole opens only where a near sector is ready, so there is never a gap).
2. Workers: 2 dedicated background threads (the i3-1215U has 2P + 4E cores; Unity keeps main + render). Thread A: region worlds (one `RegionWorld.Build` at a time, nearest region first); thread B: sector builds by distance; when A is idle it takes sectors. One `PlanetSurface` per thread if a job needs it. Region worlds are obtained through a factory `Func<RegionId, RegionWorld>` so RG-169's surface base plugs in without code changes here.
3. `prefetchM` scales with speed: lead time >= 30 s at the current speed (region builds take 4-21 s), floor 2 km.
4. A sector requested before its region world is ready is **not** built from a fallback; it waits (the far layer keeps covering it). Count such waiting sectors inside 600 m.
5. Caches: region LRU and sector LRU with a managed-memory cap; evict outside unload radius / prefetch set first.
6. Experiment `src/WhatIf.Planet.Runtime.Experiment` + runner `tools/whatif-runtime/run-runtime.ps1` (takes the measurement lock and **waits** for it; refuses while a `NightRacer*` player — not a `*Tests` process — runs; `-NoDocs` writes to the raw folder). Real wall-clock time with real threads (the point is whether workers keep up), 60 Hz frame pacing:
   - **drive-4x:** ground vehicle at 120 m/s (4 x 108 km/h, a stress test: keeping up at 4x proves 1x) for 300 s on a great-circle path that crosses at least 3 region borders and one cube edge, seed 1, starting in a land region with roads;
   - **cold spawn:** teleport to a new region with empty caches, measure until the 600 m near set is complete;
   - **flight:** 250 m/s at 5 km altitude for 60 s (only the far layer should work).

## Acceptance (rows, group t; protocol unless "report")
- **t1 main thread:** `Update` + far selection + integration per frame (no GPU upload, there is none yet) P95 **<= 1.0 ms**, max **<= 4.0 ms** in drive-4x and flight.
- **t2 no holes:** after the first 10 s of drive-4x: frames with a wanted near sector inside 300 m that is not ready = **0**; far-layer coverage (`FarChecks` f1 style, 3000 random directions + all hole-edge vertices, every 10th frame) = **0** violations. Waiting sectors inside 600 m: report (count, max wait).
- **t3 region lead:** every region the camera enters in drive-4x was ready >= **5 s** before entry (report the minimum lead); entries without a ready region = **0**.
- **t4 throughput:** sector builds/s per thread, queue length max, request-to-ready P95 (report); worker CPU share (report).
- **t5 cold spawn:** time until the 600 m near set is complete (report; target <= 30 s incl. the region build — FAIL is reported, not tuned).
- **t6 memory:** managed memory of all caches after drive-4x **<= 150 MiB** (planet layer RAM budget, RG-153 Q4) and no growth over the last 100 s (slope report, must be <= 0.1 MiB/s).
- **t7 flight:** 0 near sectors requested above 1500 m ground clearance; t1 holds.
- **t8 determinism:** 200 sampled sectors from the streamer bit-identical to a direct `SectorBuild.Build` of the same sector in a fresh process.
- **t9 no regression:** `scripts/check.ps1` + `scripts/verify-hygiene.ps1` exit 0 (`WhatIf.Planet.Runtime.Tests` in `scripts/test.ps1` and the sln); unit tests for the wanted-set computation (radius, hysteresis, altitude cut) and the hole-only-when-ready rule. Full run **<= 8 min**.
- A failing protocol row: optimise inside this ticket first (e.g. job priority, integration cap, prefetch). If it still fails, report FAIL with numbers and the cause; the orchestrator decides at review.
