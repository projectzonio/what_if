## Current state (read first: `wiki/entity/what-if-planet-viewer.md`, `.planning/race-game/docs/what-if-planet-viewer.md`)

- Content: anchor sectors (`AnchorSector.Build(w, sec, o)` -> `AdaptedSector` 65 x 65, ~4.7 m spacing) + far layer (`WhatIf.Planet.FarLayer`, CDLOD quadtree level 0..13 per cube face, horizon + frustum culling) via `PlanetStreamer`. Near sectors stop above 1500 m altitude; the far layer selects from level 0, so the library already supports any altitude.
- Colour today: height / forest / "carved ground" flag (|Contribution| > 0.05 m) -> whole settlements grey, roads invisible. Sea = a water cap mesh rebuilt around the origin at every rebase (~400 km radius) — it cannot cover the globe from orbit.
- RG-179 numbers (i3-1215U/UHD): fly +0.85 ms P95 (low) / +3.23 ms (max) over the empty scene; RAM +44..63 MiB; main-thread `MeshCollider` assign 2.6-4.8 ms per sector (several per sector crossing) — `-Bake thread` measured 0.03 ms with no worse P99; unexplained 37-66 ms frame max in 300 s drive rows (not in the 340 s repeat); v5 magenta below the horizon at p3 1000 m (1 px) / 5000 m (2868 px), cause not verified.

## Design (orchestrator — simplest mechanism first)
1. **Roads (library, additive):** `AnchorSector.Build` already computes per vertex the distance to the nearest corridor edge (`bestEff`, line ~109) — emit it. Add an optional per-vertex surface code to `AdaptedSector` (e.g. `byte[] Surface`: 0 ground, 1 corridor road, 2 settlement street, 3 shoulder), filled in `AnchorSector.Build`; settlement streets from the settlement world's road network (`sw.Gen`, find the query WorldGen already has for road distance — `src/WhatIf.WorldGen` is read-only, call its API). Heights, `Contribution` and every existing hash must stay bit-identical (golden + RG-175 hash + anchors tests). Viewer colours by the code (asphalt dark grey, street lighter, shoulder gravel). 4.7 m vertices give jagged ~2-vertex roads: acceptable for v1 if roads read as continuous lines in the shots; if not, per-sector mask texture (64 x 64 -> 256 x 256 R8) sampled in the shader — measure, choose one, do not keep both.
2. **Orbit:** new spawn `orbit` (e.g. 20 000 km over P1) and run `--stream-run orbit`: camera descends from orbit to 50 m over P1 along a log-altitude path in ~120 s, then holds. Sea in the far node meshes (vertices below sea level drawn at sea level with sea colour, or a sea flag), so the water cap is needed only near the ground or not at all. Camera near/far planes scale with altitude; check depth precision (URP reversed Z) — no z-fighting at the coast from 1000 km. Floating origin keeps working at altitude (rebase by distance, origin may sit on the camera).
3. **Colours/relief:** slope + height tint (beach, lowland, upland, rock, snow by height/latitude), forest darker, lambert without the washed SH ambient; atmosphere/horizon haze only if it is one fog term. No textures, no trees/buildings (separate lanes).
4. **Micro-lags:** make thread collider bake the default (main path keeps `-Bake main` as an option for the row). Add a spike log: every frame > 16.7 ms records the streamer events of that frame (sector integrations, far node builds, rebase, collider assign, water rebuild, GC count). Fix the cause found, inside the viewer.
5. **v5 holes at 1/5 km:** one diagnostic batch with the spike/selection data (`Selection.Nodes` count, near/far border, sea cap edge). With the sea in the far layer the cap cause disappears by construction; if holes remain and the cause is a library bug in `FarLayer`, report it with numbers (read-only), do not tune around it.
