## Design (orchestrator — simplest mechanism first; choose one per item, delete the losers)
1. **Stall exits (rows r4, s3 cold):** first make `Experiment seg` take a segment id argument instead of its hard-coded segment (RG-181 follow-up). Then print the 9 B segments: joint grades, cut/fill bounds and crest radius at the stall.
   - Candidate (a): reuse RG-182's pinned-start slack (cut/fill bounds widen 8 m over the first 150 m) at **both pinned joints of every corridor segment**, planet only (spec flag, NightRacer default off).
   - Candidate (b): slide a joint by up to N stations to the nearest feasible station before the solve.
   - Measure both on the 9 segments, keep one. A ground-crest cost term in routing is option (c), only if (a) and (b) fail.
2. **Memory (row s4):** after a settlement world is built, keep only what `AnchorSector.Build` reads: the terrain model, the street edge cell grid used for `Surface`, and the entrance data. Drop the graph and road samples. Add a byte-capped LRU only if the drop alone misses <= 3x. The cached result must stay deterministic: rebuilding a dropped world must give bit-identical sectors (r7, s1).
3. **Street footprint (row s2):** in `AnchorSector.Build`, carve street vertices (the RG-183 street mask) to the settlement road height also where the blend weight < 1, with the same carve falloff the corridor uses. Corridor-only sectors keep their pinned hash `5EB2BE55025B8900`. Settlement sectors change on purpose: report old/new hash.
4. **Runtime close-out (B5):** `PlanetStreamer` with anchor content (the RG-178 constructor) drives along `CorridorPath` **from one city centre to another** across >= 3 old region borders (and a cube edge if a path offers one), at 30 m/s and 120 m/s. Run the full t-row set of `what-if-planet-runtime.md` with unchanged budgets. Add one row: road continuity, meaning that at every old region border the path crosses, the vertices under the path centre line have `Surface` = corridor/street (0 gaps).
