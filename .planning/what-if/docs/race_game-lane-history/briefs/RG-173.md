## Why
User, 2026-11-12 ~22:15 (overnight mandate, verbatim): „planetary engine dostává přednost- dostat dlaždice na planetu. Dlaždice multiplikuj + lesy, jezera, moře, oceán. HW je limitovaný, jsou potřeba optimalize už v průběhu testů. ... Jde o výsledek, ne o způsob.“
RG-172 proved the streaming runtime on the old (pre-surface) region base: 0 holes at 4x speed, but **region world builds are the bottleneck**: `RegionWorld.Build` 5-70 s per 10 km region, ~12 gen0 GC/s (3 768 in 300 s, 1.4 s total pause) while building. RG-169 measured `BuildSurface` at 2.1-2.8 s sequential but up to 53.9 s when regions build in parallel under load. In Unity (Mono, stop-the-world GC) the allocation rate becomes main-thread hitches, so it must drop before the viewer ticket.

## Design (simplest thing that meets the rows; you may improve it, say why in the outbox)
1. **Factory switch (small):** `Scenarios.Factory` -> `id => RegionWorld.BuildSurface(id, Seed)` (one `PlanetSurface` per worker thread if `BuildSurface` needs it; check thread-safety of a shared instance first and say which you chose). `Scenarios.HeightFunc()` must return the same surface height the region base uses, else t2 coverage compares against the wrong far layer — check and align (the far layer's height function is the streamer's `heightFunc`). Path: keep RG-172's drive-4x path (3 region borders + 1 cube edge); report land/water share along it.
2. **Profile first (one cycle):** wrap each `Generator.Execute` stage (`PlaceSettlements`, `BuildMotorway`, `BuildStreets`, `BuildInterchange`, `ConnectPrimary`, `ConnectSecondary`, `Assemble`) plus `MatchWidthsAtDegree2Nodes`, `TerrainModel.Bind` and the `RegionWorld.BuildSurface` work outside `Generator.Run` with `Stopwatch` + `GC.GetAllocatedBytesForCurrentThread()`. Profiling hooks must not change output; a static `Action<string,double,long>` callback that is null by default is enough. Measure 9 regions (block B of RG-169: `F0.L10.r159..161.c1022..1023`, `F2.L10.r1023.c159..161`) sequentially, then the same 9 on 2 threads (`Parallel.For` with MaxDegreeOfParallelism 2, the runtime's worker count).
3. **Optimise the top two stages by allocated bytes** (one measured cycle per lever): typical levers — reuse buffers / `List<T>` capacity instead of per-call `new`, structs instead of small classes in hot loops, avoid LINQ / closures / boxing in inner loops, avoid `V2[]` copies of centrelines, spatial index queries that return into a caller-owned list. **Output must stay bit-identical** (rows b4). No algorithm change, no different random draws.
4. If `BuildSurface` (outside `Generator.Run`) dominates, it is owned too (see ownership) — same rule: bit-identical.

## Acceptance (rows, group b; protocol unless "report")
- **b1 runtime on the surface base** (drive-4x 300 s, cold spawn, flight, as RG-172): t1 main thread P95 **<= 1.0 ms**, P99.9 **<= 2.0 ms**, frames > 4 ms reported with count; t2 **0** frames with an unready wanted sector inside 300 m after 10 s and **0** coverage violations; t3 entries without a ready region **0** (min lead reported); t6 cache memory **<= 150 MiB**, slope over the last 100 s **<= 0.1 MiB/s**; t7 0 near sectors above 1500 m; t8 200/200 bit-identical. t4/t5 report (cold spawn target <= 30 s).
- **b2 profile (report):** per stage, before and after: median / max ms and allocated MB per region build, sequential and 2-parallel; total per build; parallel/sequential time ratio.
- **b3 cost (protocol):** allocated bytes per region build (median over the 9) **-50 %** vs the baseline measured in this ticket; sequential median build time **not worse** (<= +5 %); gen0 collections per second in drive-4x **-50 %** vs the baseline run in this ticket (same path, same build). Region build P95 in drive-4x reported.

## Machine rules
- CPU only, no Unity/editor/GPU. Measure under the measurement lock (`.git/nightracer-measure.lock` in the main checkout): `run-runtime.ps1` waits for it; for your own profile console runs wait for it too (a loop before `Enter-MeasureLock`, it throws when held). Compare timings only within the same quiet session; baseline and after run back to back.
- Size target: 300-700 changed lines of code. Above ~1000: stop and write in the outbox why.
- Known flaky test: `NightRacer.Physics.Sdk.Tests` "zero bytes allocated" can fail once in a full `check.ps1`; rerun that runner alone, report both.
- Break the loop: one optimisation cycle per lever, measured; long runs in the background with a completion notification, not polling.
- `WhatIf.WorldGen` also feeds the NightRacer game (Unity) — any output change there is a regression even if the planet rows pass; the golden hash test is the guard.
