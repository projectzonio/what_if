## Diagnosed cause (confirm first, one run)
`FarParams.MorphFraction` (`src/WhatIf.Planet.FarLayer/FarNode.cs:92`) auto = `max(0.02, min(0.3, 0.5 - 0.725 * 1250 / Range13 - 0.01))`. The comment above it derives the T-junction-safe bound `f <= 0.5 - 0.725 * nodeSide / LodRange(l)`. At `Range13 = 1800` the safe value is **-0.013**, so the 0.02 floor already broke the guarantee in RG-171; the old surface heights happened to pass. Also `MorphFactor` takes `min(distance to camera, distance to ground point)` — check that the bound still holds with the ground point (the derivation assumes camera distance only).

## Design (simplest; you may improve it, say why in the outbox)
1. Make the guarantee hold by construction: choose `Range13` so the safe bound >= the floor with margin (bound >= 0.02 needs `Range13 >= ~1930 m`; e.g. 2000-2200 m), or use the true level-13 node side/diagonal for the face position instead of the 1250 m constant if that is tighter and still conservative. A unit test asserts `MorphFraction <= safe bound` for the defaults.
2. Skirt: calibrate on **all** cameras of both seeds (or a fixed floor of 3.0 m), so the protocol row cannot pass on one seed and fail on the other.
3. Node cap: a larger `Range13` raises the node count. Measure; if > 400, move the cap with a justification from the triangle budget (<= 250 000) and f4 selection time (<= 1.0 ms) — What If mandate, the orchestrator decides at review.
