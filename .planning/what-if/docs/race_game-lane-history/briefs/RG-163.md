## Diagnosis (orchestrator — start here, verify it first)
- `Portal.Snap` clamps `s` into `[25600, LengthCm - 25600]`, so a snap can move a portal by **at most 256 m**. The RG-162 run reports **max shift 368.7 m**. So at least one portal had `s < 0` or `s > LengthCm` **before** the snap: the crossing point near a region vertex was attributed to a border whose segment it does not lie on (likely a diagonal pass through a 4-region vertex, or a 3-region cube vertex, resolved via an intermediate region whose border the arc only touches on its extension).
- Each portal is then snapped independently (`Analyse`, RoadChecks.cs ~line 110), so two portals of one vertex pass can move in different directions -> the zigzag the RG-162 worker saw.

## Design (simplest thing that meets r2)
1. **Measure first:** in `Analyse`, count portals whose raw `s` is outside `[0, LengthCm]` before the snap, and print the arc (endpoints, nearest vertex, distances) for the max-shift and max-length-change arcs. Put the count into the CSV as a new `r2 protocol` row "portals off their border segment before the snap, count, = 0". Confirm the diagnosis in the outbox before fixing.
2. **Fix the attribution** in `RoadArc.Crossings`: a crossing must lie on the border segment it is assigned to (0 <= s <= LengthCm, with a tolerance of a few cm for the quantisation). When the arc passes a region vertex diagonally, emit the crossings in the right order through the region it actually traverses (test both neighbours of the vertex; pick the one whose border segment contains the intersection). Keep the r1 invariants (s bit-identical from both sides, 0 unresolved).
3. **Joint snap:** all crossings of one arc that lie within 256 m of the **same** region (or cube) vertex form one group. Move the group to the side of the vertex the road already passes: shift the road's closest-approach point radially away from the vertex to 256 m (+ 1 cm), recompute the group's intersections with their borders from that shifted line, quantise to int64 cm, and keep r1's canonical `s`. Portals outside any group are not moved. Do not snap each portal on its own any more (delete that path, keep `Portal.Snap` only if still used).
4. Length is measured as before (polyline through the portals vs the true arc). If some short arc still exceeds 0.5 %, report it as FAIL with the arc's length, pass distance and shift — no threshold change, write the evidence under "Decisions for the orchestrator".
