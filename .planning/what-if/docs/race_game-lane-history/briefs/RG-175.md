# RG-175 — What If planet: region build time — cheaper VerticalCurves for the planet only (CPU, numbers)

Read AGENTS.md, the pool README, `.planning/race-game/tasks/RG-175.md`, then `agent_pool/shared/reviews/RG-173.md` (rows b1-b5, decision 2) and `.planning/race-game/docs/what-if-planet-runtime.md`.

## Why
A What If region world (`RegionWorld`, `Generator.Run` on the planet base) takes **8-28 s** to build; in the land drive P95 ~30 s, max ~49 s (RG-173 rerun). The prefetch lead at 4x speed is only 24.8-25.3 s min, so a slow region would leave a hole. RG-173's profile: **~99 % of the build is `GeneratorTerrain.VerticalCurves`** (`src/WhatIf.WorldGen/GeneratorTerrain.cs:201`), called per road from the refit loop (`:507`, `:512`). Allocation is already fixed (RG-173: 37.9 MB/build, gen0 0.28/s) — this ticket is about arithmetic.

## Current state (facts, verified 2026-11-13)
- `VerticalCurves` = SOR projection sweeps (`VcRelax 1.95`) on the curvature half-spaces, then `SolveProfile` (bounds, pins, grade cap) with the rounded profile as target; loop `VcOuter 30000` x `VcSweeps 20000`, both capped by `VcWorkBudget = 600 000 000` station updates per call (`:18`; added because seed 8 ran > 10 min). Stop when no station exceeds the limit by > `VcStopTol 1.01`; returns stations beyond `VcCountTol 1.02`. Gauss-Seidel/SOR on a long road converges slowly (error modes of the whole road length).
- The limit is `1 / (WorldRules.VRadiusMin(class, crest|sag) * spec.VCurveScale)`; `WorldSpec.VCurveScale` (`Rules.cs:230`, spec `terrain.vcurve_scale`) already exists. **Lowering it is the last resort** — it changes the design radii (quality), not the cost.
- The planet spec comes from `SectorAdapter.Spec(regionSeed)` (`src/WhatIf.Planet.WorldGen/SectorAdapter.cs:36`), used by `RegionWorld` (`RegionWorld.cs:71`) and the sector `TerrainModel`.
- Golden hashes that must not move: `tests/WhatIf.WorldGen.Tests/Program.cs:574/585` (terrain `0xD221EBA2351460E0`, road dataset hash of `Run(spec, rules, null)`), `tests/NightRacer.Streaming.Tests/Program.cs:250` (road hash seed 12345 `14093109894848194394`).
- Measurement tools: `tools/whatif-runtime/run-profile.ps1 -Label before|after [-Compare <dir>] [-Drive -Path land]` (rows b2-b4: 9 regions sequential, GenResult SHA, 200 sampled sectors), `tools/whatif-runtime/run-runtime.ps1 -NoDocs` (t-rows). Both take the measurement lock.

## Design (simplest first; you may improve it, say why in the outbox)
1. **Diagnose (one profile run, before any change):** per `VerticalCurves` call log road class, stations `m`, outer iterations, work used, budget hit yes/no, violations at entry and at exit, time. Answer in the outbox: is the time in a few calls that **hit the work budget** (bounds contradict the curve; the extra work buys nothing) or in **slow convergence** of many calls?
2. **Lever by the diagnosis, planet-only through a new `WorldSpec` field whose default = today's behaviour** (e.g. `VcStallOuter` = 0 off; or `VcWorkBudget` from the spec; or a faster solve of the same constraints). Candidates, cheapest first:
   - budget-bound calls dominate -> **stall exit**: stop when the violation count/maximum excess has not improved over N outer iterations; the remaining violations are reported as today (vcBad + `RelaxBasinBounds` path unchanged);
   - slow convergence dominates -> fewer, better sweeps (e.g. coarse-to-fine: solve on every k-th station first, then refine; or a direct banded solve of the active constraints). Must stay deterministic (no threading inside, no time-based exit).
   `SectorAdapter.Spec` sets the new field. `Generator.Run(spec, rules)` for NightRacer seeds gives a bit-identical `GenResult`.
3. Re-baseline the planet: `run-profile.ps1 -Label before` on main code first, then `-Label after -Compare <before dir>` — b4 rows will differ by design (planet outputs change); report it, do not "fix" it. t8 determinism (same build twice) must still be 200/200.
