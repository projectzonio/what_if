Near the car the world is drawn by 65 x 65 sectors at ~4 m (level-15 quadtree leaves, `LoadRadius` 600 m). Everything beyond that — the rest of the region, the coast 20 km away, the horizon from a hill or a plane — needs a **far layer**: a coarse mesh of the whole planet with a hole where near sectors are loaded. This ticket builds and measures it on the CPU (Unity licence is expired; no GPU numbers yet), so the later Unity viewer only uploads what this library selects.

## Design (simplest thing that answers the questions; you may improve it, say why in the outbox)
New library `src/WhatIf.Planet.FarLayer` (netstandard2.1, C# 8, references `WhatIf.Planet` + `WhatIf.Planet.Surface`, no Unity, no packages). Height source behind `Func<Vec3, double>` (pass `PlanetSurface.Height`; tests may pass `PlanetNoise.Height`).

1. **Nodes = the existing equal-angle quadtree.** A node `(face, level l, row, col)` with `l` in 0..13 covers `2^(21-l)` lattice steps; it has **17 x 17 vertices** (16 x 16 quads) at lattice indices (spacing `2^(21-l) / 16` steps — an integer for every l <= 17), so every far vertex is a lattice vertex: evaluate edge/corner vertices through `Lattice.Canonical` -> neighbouring faces share bits (row f8). Finest far level **13** (~1.2 km nodes, ~76 m spacing): a level-13 node contains exactly 4 x 4 level-15 sectors = 4 x 4 quads each.
2. **Selection (CDLOD, Strugar):** recursive from the 6 face roots with **3D distance** from the camera (double) to the node's bounding box (corner directions x [R + hmin, R + hmax] — store hmin/hmax per node when it is built; before that use the parent's range); LOD range per level `range[l] = range[13] * 2^(13-l)`, `range[13]` your tuning (start ~2.5 km); **horizon culling** (drop a node whose whole box is below the horizon of the camera sphere point, conservative with hmax); optional 90° frustum (report both "all around" and "frustum" counts). Neighbouring selected nodes differ by at most 1 level (row f8; CDLOD gives this with ranges doubling).
3. **Morph:** per vertex morph factor from the 3D distance in the last 30 % of the node's range; odd vertices move to the midpoint of their even neighbours (the parent's position). Pure CPU function here (the shader does it later): row f7 checks that at morph = 1 every vertex equals the parent mesh position.
4. **Hole mask at sector granularity:** the near set = level-15 sectors whose centre is within `LoadRadius` 600 m (the streaming rule today). A level-13 node gets a 16-bit mask of its 4 x 4 sectors that are near -> those 4 x 4 quads are not drawn; a coarser node that would overlap a near sector must be refined to level 13 (force-split by distance to the near set). **Skirt:** on every quad edge that borders a dropped quad, a vertical strip down by `skirtM` = measured max |near - far| on the hole edge (row f2) x 1.25, rounded up to 0.5 m; report its triangle count.
5. **Build + cache:** node build = 289 `Height` calls (+ hmin/hmax); bounded LRU of built nodes (memory row f6). Per frame the selector requests nodes; build at most what fits in **2.0 ms per frame** (queue by distance); a requested node that is not built yet is drawn by its built parent (never a hole: row f5). The 6 roots + level 1..3 are prebuilt at start (report that time).
6. **Experiment console** `src/WhatIf.Planet.FarLayer.Experiment` + runner `tools/whatif-farlayer/run-farlayer.ps1` (copy the pattern of `tools/whatif-surface/run-surface.ps1`: refuse while a `NightRacer*` player runs, take the measurement lock via `tools/game-unity/measure-lock.ps1` — RG-170's runner takes the same lock, wait for it; Release build; cost rows in 3 separate processes; raw output `artifacts/whatif-farlayer/<stamp>/` git-ignored, sha256 list). Report writes `.planning/race-game/docs/what-if-planet-far-layer.{md,csv}` (columns row, kind protocol|report, value, threshold, result, note).
7. **Cameras (seed 20261112 plus one more seed for f2):** (a) 2 m above a land point at the coast, (b) 2 m above a lake shore, (c) 300 m above land, (d) 10 km above land (plane), (e) **drive**: 120 s at 30 m/s (108 km/h), 2 m above ground along a great circle that crosses a cube edge, 60 frames/s, near set updated per frame; (f) **flight**: 120 s at 250 m/s at 5 km. Camera points come from `PlanetSurface` (find a coast / lake shore with the RG-168 tools, name the directions in the doc).
8. **Images (for the orchestrator)** into the raw folder as PNG (reuse RG-168's PNG writer pattern, copy, do not reference the experiment project): per camera (a), (c), (d) a top view of the selected nodes (colour by level, hole in black, skirt edges red) on the face around the camera; one equirect overview of the node levels for (d).

## Acceptance (rows)
- **f1 coverage (protocol):** for each camera (a)-(d) and every 10th frame of (e)/(f): 100 000 random directions within the horizon + all 65 x 65 vertex directions of the near sectors -> each direction is covered **exactly once** (by one selected far quad that is not masked, or by one near sector); violations = **0**.
- **f2 near/far gap (report + protocol):** on every hole-edge vertex (near sector border), |`SurfaceSector` height - far mesh height interpolated at the same direction (the far triangle containing it, morph applied)|: max, P95 per camera and seed (report); `skirtM` covers 100 % of the measured gaps (protocol). Note: WorldGen carve/fill near roads adds to this gap later (RG-169 measures it) — report the surface-only number here.
- **f3 draw budget (protocol, UHD-sized):** visible far triangles **<= 250 000** and selected nodes **<= 400** for every camera and every frame of (e)/(f) (all around, i.e. without frustum culling; report frustum numbers too). Skirt triangles included.
- **f4 selection cost (protocol):** selection + mask per frame, single thread, median of 3 processes **<= 1.0 ms** (P95 report) per camera and over (e)/(f).
- **f5 streaming (protocol):** in (e) and (f): node build ms per frame P95 **<= 2.0 ms** (max report), frames where a selected node has neither itself nor its parent built = **0**, nodes built per second report; startup prebuild time report.
- **f6 memory (protocol):** managed memory of the node cache after (e) + (f) **<= 64 MiB** (planet layer RAM budget 150 MiB, RG-153 Q4); report vertex bytes per node.
- **f7 morph continuity (protocol):** at morph factor 1, max |vertex - parent mesh position| **< 1 mm** on 1000 nodes; at morph 0 the vertex equals its own height bits.
- **f8 seams (protocol):** every edge vertex shared by two selected nodes of the same level (incl. across cube faces) bit-identical = 0 differing; adjacent selected nodes differ by **<= 1 level** = 0 violations; T-junction gap between a level l and l+1 neighbour after morph < 1 mm.
- **f9 no regression:** `scripts/check.ps1` + `scripts/verify-hygiene.ps1` exit 0 (`WhatIf.Planet.FarLayer.Tests` in `scripts/test.ps1` and the sln). Unit tests: f1 on a fixed camera, f7, f8 cross-face edge bits.
- A failing protocol row: optimise inside this ticket first (overnight mandate: "optimalize už v průběhu testů") — e.g. a lower `range[13]`, a coarser 9 x 9 node grid at levels < 8, frustum culling counted in f3 only if the all-around number cannot meet it (say so). If it still fails, report FAIL with numbers and the cause; do not tune thresholds after the fact (the orchestrator decides at review under the What If mandate).
