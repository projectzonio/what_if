## Why
RG-166 (accepted 2026-11-12): RG-165's gnomonic tangent-plane **chart** stays — it is a chart, not geometry: vertices are always the exact canonical lattice direction `d * (R + h)`, WorldGen is only *asked* at the chart point (x, z). Error <= 1.5e-9 per sector, <= 1.6e-6 over a level-10 region. Per-sector charts force a taper on every quad edge (38-45 % of the area) and change coordinate system every 216-306 m, so roads cannot cross a sector. **v2: anchor the same chart at the level-10 region centre (`RegionPlane`), generate one WorldGen world (terrain + roads) per region, sample every sector of the region from it, and taper the WorldGen contribution only on region borders** (1.3-1.6 % of the area). This is also RG-165's "next step" (roads in a sector) in its cheapest form: roads now cross sector borders for free inside a region.

## Design (simplest thing that answers the questions)
1. **Generator hook** (`src/WhatIf.WorldGen/Generator.cs`, the only NightRacer file you may change): `Generator.Run(spec, rules, Func<double,double,double> baseHeight)` overload; the private ctor passes it to `new TerrainModel(spec, baseHeight)`. `baseHeight == null` -> current behaviour, bit-identical (existing `Run(spec, rules)` calls the overload with null). One regression test in `tests/WhatIf.WorldGen.Tests` (graph + `Height` hash at a fixed seed unchanged with null).
2. **`RegionWorld`** (new, `src/WhatIf.Planet.WorldGen/`): for a `RegionId` + world seed: chart = `RegionPlane` (U, E, N of the region centre); base height `B(x, z) = PlanetNoise.Height(normalize(R U + x E + z N))` (direct, no 16 m grid — RG-166 §6 says ~0.2 ms per 65 x 65); `WorldSpec` = RG-165's `SectorAdapter.Spec(regionSeed)` with `SizeKm` sized so the square covers the region's chart footprint (report the size per site; the region is 9.78 x 9.78 km at a face centre, 9.78 x 6.92 km at a cube-edge midpoint, a 9.22 km 120° rhombus at a cube vertex); `Generator.Run(spec, WorldRules.Synthetic(), B)`. Content outside the region polygon is simply cut by the region-border taper (polygon domain = later, row e5). Cache one `RegionWorld` per region in the experiment.
3. **Sector build v2** (`SectorAdapter` v2 entry or a new class; keep v1 + w-rows working): for each of the 65 x 65 lattice vertices: region chart point (x, z) of the vertex direction, `h = B + taperRegion(dist to the region border) * (T(x, z) - B(x, z))` with T = the region world's carved `Height`; vertex = `d * (R + h)`. Taper: 32 m smoothstep, distance = chart distance to the region polygon's sides (great circles = straight lines in the chart). Sample in one batch per sector (box query like `SampleTile`, or a vectorised loop — your choice, measured by e10). **Triangles:** emit the index order that splits each lattice quad along its shorter diagonal (matters at cube vertices: 4.50 vs 7.80 m).
4. **Experiment rows**, new group `e` in `WhatIf.Planet.Experiment` (same CSV columns, protocol/report kinds), run by `run-experiment.ps1`. Sites: face centre, cube-edge midpoint, cube vertex (as RG-166 §2) + one region corner where 4 regions meet; 3 seeds:
   - **e1** shared lattice vertices of neighbour sectors **inside one region**, at least one pair where a generated road crosses the sector border: differing height bits = **0**, protocol. Report how many shared vertices lie on a road.
   - **e2** seam across region borders incl. one on a cube edge and one at a cube vertex: max world gap **< 1 mm**, share of sector area inside the taper band **<= 1.6 %**, protocol; report the number of road samples inside the taper band (roads ramp there until portals carry a road height — later ticket).
   - **e3** chart metric: 10 000 random point pairs per region, chart distance vs great-circle distance, max relative error **<= 2e-6**; 1 000 right angles, max deviation **<= 1e-4 deg**, protocol.
   - **e4** WorldGen road rules after mapping to the sphere: for every road edge of the region world, 3D min horizontal radius, max grade and width per class vs their planar values, max relative deviation **<= 1e-5** (RG-166 predicts 1.6e-6), protocol.
   - **e6** carve sampling: max terrain height above the road surface inside the road footprint when sampled at the lattice vertices (3.38-4.78 m, sheared up to 30°) vs the planar 4 m `SampleTile` baseline, both diagonal choices, report (a worse value than the baseline is a finding, not a FAIL).
   - **e8** float emit: per-sector float32 local mesh + frame into a floating-origin frame at 0 / 600 m / 10 km: max gap and bit-identical count of shared vertices, report (RG-166 §4 predicts 61 µm at 600 m, 0.98 mm at 10 km).
   - **e10** cost: sector build v2 (batch sample, 65 x 65) median/P95 of 3 runs, single thread, **< 3 ms**, protocol; region world build (generator + model) time and managed memory, report.
   - All earlier rows (a)-(d), r1-r5, w1-w5 stay PASS; a/b/c + r1 bit-identical to main's `what-if-planet-experiment.csv`.
5. **Doc:** add a "v2" section to `.planning/race-game/docs/what-if-planet-worldgen-adapter.md` (region chart, hook, taper scope, e-table, what v2 leaves out: polygon domain e5, far-layer skirt e7, GPU dropouts e9, road height at region-border portals) and overwrite `what-if-planet-experiment.{md,csv}` through the generator.
