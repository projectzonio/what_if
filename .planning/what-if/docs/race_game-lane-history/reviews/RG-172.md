## Code read
- `PlanetStreamer.Update` does only bookkeeping on the main thread; workers take jobs by priority with CAS claims; hole opens only for ready sectors whose level-13 far node is built (at most one inline far build per frame). Matches the brief's design; the three changes (60 s lead x 1.5 longest build, +-12 deg prefetch cone beyond the 2 km floor, 2 region workers + 1 sector worker) are justified with measured runs in the outbox/doc. Accepted.
- Minor (not a blocker, for the viewer ticket): a pending sector job keeps a reference to its `RegionEntry`; `DropUnwantedRegions` can cancel a pending region that is not in this frame's plan, and the job would then wait on a region that is never built. With the current parameters it is unreachable (all regions within the 2 km floor are planned in every direction; near sectors reach 760 m; above 3000 m no near sectors are wanted), but a smaller floor would expose it — re-resolve the region entry when a job's region was cancelled.
- `t2-waiting` value text "max 0 sectors" (after 10 s) vs note "2 at most" (incl. start) reads confusingly — cosmetic.

## Decisions (What If mandate: adjust with a justification, report here + handover)
1. **t1 max accepted as reported.** One frame of 18 000 at 4.86 ms with `farBuilt=0`, `integrated=0` (pure bookkeeping frame); worker runs showed similar single outliers (4.9-54 ms) and none in the final one. P99.9 is 1.1-1.3 ms in every run. Likely cause: GC pauses — 3 768 gen0 collections in 300 s (~12/s, total pause 1.4 s) driven by the allocation churn of `RegionWorld.Build` on the background threads, plus OS scheduling with 3 background threads. The row is restated for What If runtime runs as **P95 <= 1.0 ms, P99.9 <= 2.0 ms, frames > 4 ms reported** (count + cause). The real main-thread budget is measured in the Unity viewer (Mono GC behaves differently).
2. **Prefetch lead 60 s / 1.5 x longest build, cone +-12 deg, 2 region workers** accepted. Region world builds (`Generator.Run`, single thread) take 5-70 s and are the bottleneck of the whole planet runtime (t3 min lead 19-33 s at 4x speed).
3. **Region factory without the surface base** accepted: the numbers use `PlanetNoise` only; after RG-169 merges, the orchestrator reruns `run-runtime.ps1 -NoDocs` with `RegionWorld` on the surface base (`RegionWorld.Scatter()` too) and compares t3/t6.
